레이어관리

이미지의 크기를 줄이기

보통 현업에서는 이미지를 빌드하고 푸시하고 배포하는 과정은 모두 각각 다른 기기에서 수행
새로운 버전으로 빌드한 이미지를 레지스트리에 푸시
각각의 환경에서 이미지를 레지스트리로부터 다운받아 컨테이너 업그레이드

이 과정에서 이미지는 네트워크를 통해 업로드되고 다운로드되기 때문에
이미지 크기가 작은 것이 배포 속도와 네트워크 사용량에 더 유리

Run 지시어는 &&를 활용해 최대한 하나로 처리

애플리케이션의 크기를 가능한 작게 관리

  • 필요 없는 파일 및 디렉토리 제거
    • 코드 저장소에 있는 불필요한 파일(예: 로그 파일, 캐시, 문서, 테스트 파일 등)을 제거
    • .dockerignore 파일을 사용하여 빌드 과정에서 Docker 이미지에 포함되지 않도록 설정
  • 종속성 최소화
    • 애플리케이션이 사용하는 라이브러리나 프레임워크의 의존성을 검토하여 실제로 필요한 것만 포함
      예시: python-requirements.txt 파일을 정리, Node.js-package.json의 종속성을 최소화
  • 멀티스테이지 빌드 활용
    • 애플리케이션 빌드 도구나 중간 결과물을 최종 이미지에서 제거

베이스 이미지는 가능한 작은 이미지를 사용. 예시: alpine OS

보통 alpine OS를 기반으로 제작된 이미지를 베이스 이미지로 많이 활용 nginx나 JDK 같은 도커 허브에 업로드 되어 있는 이미지들도 태그에 알파인이 붙어 있는 이미지들이 있음

극단적으로 사이즈를 줄이려면 모든 이미지의 가장 뿌리가 되는 이미지인 스크래치 이미지를 활용할 수도 있음
scratch image: 아무것도 포함되지 않은 “빈” 이미지
스크래치 이미지는 이미지를 빌드하기 위한 가장 최소한의 파일만 포함한 이미지
스크래치 이미지 위에서 필요한 것들만 패키징하는 것이 보안에도 뛰어나고 이미지의 크기도 가장 작게 만드는 방법

scratch는 운영 체제가 포함되지 않기 때문에, 시스템 라이브러리나 쉘, 패키지 관리자가 필요 없는 프로그램만 사용할 수 있음
-> Go, Rust, C와 같은 컴파일된 언어로 빌드한 애플리케이션을 실행할 때 사용
이런 언어들은 이미 실행에 필요한 모든 바이너리를 포함하고 있어서, 별도의 운영 체제 환경 없이 직접 실행할 수 있음

실제로 하나의 컨테이너의 크기를 줄이는 것이 중요한 미션 중의 하나인 MSA 아키텍처에서는 go 언어를 사용하는 경우도 많음
여러개의 서버를 운영하는데 있어서도 네트워크 사용량이 줄어들고 공유하는 속도가 빨라지기 때문에 서버의 크기를 줄이는 것에 대한 장점을 많이 누림

Docker Compose

여러개의 도커 컨테이너들을 관리하는 도구
큰 장점 중 하나는 로컬 개발 환경에서 활용하기 편리
개발자는 자신의 pc에서 자신이 개발하는 프로그램 뿐만 아니라 DB 서버나 애플리케이션과 연관이 있는 다른
애플리케이션 서버도 함께 실행해야 하는 경우가 있음
이런 환경들을 실제 운영 환경과 비슷한 방식으로 개발 PC에서 빠르게 환경을 구성할 수 있음

docker-compose.yaml이라는 정의서 파일을 사용해 관리할 컨테이너를 정의
yaml: 데이터를 표현하기 위한 포맷 중 하나. e.g. JSON yaml은 JSON과 유사하지만 JSON은 {}, “",가 필수인 반면 YAML은 띄어쓰기 기반으로 정보 구분

오케스트레이션 도구인 Kubernetes에서도 리소스를 정의하기 위해 YAML 문법을 사용

docker compose up -d # YAML 파일에 정의된 서비스 생성 및 (백그라운드로)시작(이미지 빌드&실행)

docker compose ps # 현재 실행 중인 서비스 상태 표시

docker compose build # 현재 실행 중인 서비스의 이미지만 빌드(이미지 빌드만, 실행x)
# yaml 파일에 정의된 service중에 build 옵션이 있는 서비스를 찾아서 이미지를 먼저 빌드

docker compose logs # 실행 중인 서비스의 로그 표시

docker compose down # YAML 파일에 정의된 서비스 종료 및 제거

docker compose down -v # 볼륨도 제거

기존에는 도커 파일을 사용해서 이미지를 build하고 네트워크를 구성해서 컨테이너를 실행시킨 다음
컨테이너가 사용할 다른 서버(e.g. db서버, nginx)도 도커 런 명령으로 실행시켜야 함

이 과정을 docker compose로 한번에 실행할 수 있음
