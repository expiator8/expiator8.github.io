동기와 비동기

동기와 비동기

Nov 13, 2024
6 minute read

목표

먼저 Process와 Thread를 간단하게 정리하고 동기/비동기 개념 및 용어를 정리하고 간단한 코드로 테스트

프로세스

  • 메모리를 할당받아 실행되고 있는 프로그램

프로세스 구성요소

PCB(Process Control Block)

  • 운영체제가 프로세스를 제어하기 위한 정보를 저장해 놓는 구조체

PID(Process Identification Number)

  • 프로세스 고유 번호

PC(Program Counter)

  • 프로세스를 실행하기 위해 다음으로 실행할 기계어가 저장된 메모리 주소를 가리키는 값

메모리

  • 참조

프로세스 메모리 구조

Text(Code) 영역

  • 실행할 프로그램의 코드가 CPU 에서 수행할 수 있는 기계어 명령 형태로 변환되어 저장되는 공간
    CPU는 이 영역에서 명령어를 하나씩 가져와 처리

Data 영역

  • 전역 변수(global variable) 또는 static 변수 등 초기화 된 전역변수를 저장하는 공간
  • 프로그램이 시작될 때 할당되어 프로그램 종료 시 소멸
  • ROM(Read Only Memory) 섹션

BSS(Block Stated Symbol) 영역

  • 초기화 되지 않은 전역변수를 저장
  • 초기화 된 전역변수는 Data 영역에 저장되어 비휘발성 메모리인 ROM에 저장되는데 이 부분은 비용이 많이 들어 RAM에 저장될 것과 ROM에 저장될 것을 구분하기 위해 영역을 구분해 사용한다.
  • RAM(Random Access Memory) 섹션

Heap 영역

  • 필요에 의해 메모리를 동적 할당하고자 할 때 사용하는 메모리 영역(동적 데이터 영역)
  • 메모리 주소 값에 의해서만 참조되고 사용되는 영역
  • java를 예로 들면 객체가 heap 영역에 생성되고 GC(Garbage Collection) 에 의해서 정리되는 영역

Stack 영역

  • 호출된 함수의 수행을 마치고 복귀할 주소 및 데이터(지역변수, 매개변수, 리턴값 등) 등 잠시 사용되었다가 사라지는 데이터를 저장하는 영역(임시 메모리 영역)
  • 함수 호출 시 할당되고 함수 종료 시 반환
  • 프로세스가 메모리에 로드될 때 Stack 사이즈가 고정되어 있어 런타임 시 Stack 사이즈를 바꿀 수 없음

일반적으로 작성하는 코드로 만들어진 어플리케이션은 컴파일 할 때 code, data, stack 영역의 크기를 계산해 메모리 영역을 결정

커널 주소 공간

  • 메모리 구조는 크게 커널 주소 공간(kernel space), 사용자 주소 공간 으로 분리 할 수 있음
  • 커널 부분은 사용자가 접근 할 수 없음
  • stack 아래에 있다고 보면 됨

  • Code, Data, BSS 영역은 컴파일 시 크기가 결정되고 Heap, Stack 영역은 런타임 시 크기가 결정
  • Stack의 지역변수는 사용하고 소멸하므로 데이터 용량이 불확실. 그렇기 때문에 밑에서부터 채워올리고 Heap은 위에서부터 채워나감. 이렇게 서로 주소값을 채워나가다가 Heap에서 Stack 방향으로 영역을 침범하는 경우 HEAP overflow, 반대로 Stack에서 Heap 방향으로 영역을 침범한다면 STACK overflow

쓰레드

  • 프로세스 내에서 실제로 작업을 수행하는 주체
  • 프로세스 내에 메모리를 공유하면서 프로세스의 여러 특정 부분을 동시에 수행할 수 있음
  • 모든 프로세스는 한 개 이상의 쓰레드가 존재하여 작업을 수행

멀티 쓰레드 프로세스

  • 두 개 이상의 쓰레드를 가지는 프로세스

쓰레드 구성요소

  • 쓰레드는 기본적으로 프로세스에 귀속.

TCB

  • Thread Identifier: 쓰레드를 구분하는 유일한 식별자
  • Stack pointer: 쓰테드 별로 고유한 Stack의 pointer
  • Program counter: 다음에 실행될 명령어의 주소
  • 쓰레드의 상태 (running, ready, waiting, start, done)
  • 쓰레드가 소속된 processor의 PCB주소

싱글 쓰레드와 멀티 쓰레드

  • 멀티 쓰레드는 데이터와 파일들을 공유하고 각각 registers와 stack 메모리 공간을 할당받음

동시성(Concurrency)과 병렬성(Parallelism)

동시성, Concurrency

  • 동시에 실행되는 것 처럼 Time-sharing 알고리즘(시분할 등)을 이용하여 작업을 수행하는 것
  • 하나의 CPU 코어에서 여러 쓰레드를 처리하는 것이며 기본적으로 context swithcing 을 통해 자원을 공유

  • 한 작업이 “대기 상태” 일 때 다른 작업을 수행할 수 있어서 자원을 효율적으로 사용하고 I/O bound (Disk IO, Network IO)에서 특히 유용

병렬성, Parallelism

  • 동일한 시간에 독립적인 작업을 수행하는 것

  • 즉, 동시성은 하나의 코어에서 여러 쓰레드를 다중 처리하지만 병렬성은 진짜 각 코어가 동시에 독립적으로 수행

블로킹(Blocking)/논블로킹(Non-blocking)

  • 제어할 수 없는 대상의 처리 방법

블로킹(Blocking)

  • 다른 작업의 실행이 현재 작업의 실행을 막는다
  • 호출한 함수가 멈춰 있는다

  1. 함수 A, B, C가 있다고 가정
  2. 호출자가 다른 함수 A를 호출했을 때
  3. 호출자는 A의 실행이 끝날 때까지 멈추고
  4. A의 실행이 끝나고 나서야 B가 실행된다.

호출자가 제어할 수 없는 대상인 A가 제어권을 가지고 있기 때문에 호출자의 행동이 블로킹 된다. A가 완료될때 제어권을 호출자로 반환.

논블로킹(Non-blocking)

  • 다른 작업의 실행이 현재 작업의 실행을 막지 않는다
  • 호출한 함수가 멈춰 있지 않는다

호출자가 제어할 수 없는 대상인 A가 별도의 제어권을 얻어 실행되어 호출자의 행동이 블로킹 되지 않아 함수 A가 실행중인 상태로 끝나지도 않았는데 B를 호출, 마찬가지로 C도 호출할 수 있음

동기(synchronous)/비동기(asynchronous)

  • 작업(들)이 같이 시작해, 같이 끝나는가?
  • 제어권의 반환과 결과값의 전달이 같이 이루어지는가

동기

  • 작업들이 같이 시작해 같이 끝남

  • 도중에 B가 끼어든다면? 같이 시작한 것이 아님

  • 작업 중에 다른 작업이 끼어들지 못하게 하기 위해 사용

비동기

  • 작업들의 시작과 끝이 다름

  • 작업 중에 끼어들어도 괜찮음

  • 시작, 종료 시기를 신경쓰지 않기 위해 사용

동기==블로킹?, 비동기==논블로킹?

Block                              Synchronous
                           ==
Non-Block               Asynchronous

블로킹은 제어권을 호출된 함수가 들고 있다가 결과값을 반환할 때 돌려주는 것이고, 동기는 제어권을 반환하는 시간과 결과값을 반환하는 시간이 일치하는 것인데 그러면 블로킹과 동기가 같은게 아닌가? 마찬가지로 논블로킹과 비동기가 같은게 아닌가?

관점이 다르다.
블로킹/논블로킹: 제어권에 대한 관점
동기/비동기: 시간에 대한 관점. 즉, 제어권을 반환하는 시점, 타이밍의 관점

import threading

    time.sleep(3)
    return f"Task {n} is completed."

def main():
    with ThreadPoolExecutor(max_workers=1) as executor:
        future = executor.submit(long_running_task)  # 작업을 쓰레드 풀에 제출

        # 완료될 때까지 기다리며 결과 확인
        while not future.done():
            print("필요한 로그출력")
            ...
            time.sleep(0.5)  # 0.5초마다 상태 체크

        result = future.result()  # 결과 얻기
        print(result)

import asyncio
from datetime import datetime
from random import randint

async def run_job() -> None:
    delay = randint(5, 15)
    print(f'{datetime.now()} sleep for {delay} seconds')
    await asyncio.sleep(delay)  # 5~15초 동안 잠자기
    print(f'{datetime.now()} finished ({delay} sec)')

async def main() -> None:
    while True:
        asyncio.create_task(run_job())
        await asyncio.sleep(10)

asyncio.run(main())

await의 역할

  • 뒤에 나오는 코루틴(Awaitable 객체)를 Eventloop에 등록

  • 코루틴이 끝날 때 결과값을 전달받기를 기다리며 제어권을 Eventloop로 반환

  • await나 return을 하지 않는 이상 Eventloop로 제어권을 반환하고 다른 코루틴을 실행할 방법이 없기 때문에
    requests등의 블로킹 코드를 코루틴 내부에서 실행하는데 주의가 필요하다는 것.

async/await를 했을때
await를 하면 이벤트 루프가 돌지 않는가? 이벤트 루프가 돈다. 그러면 비동기라고 할 수 있지 않나?
함수 내부에서만 보면 동기/블로킹으로 작동하고 있을 것이다.
왜냐? await가 끝나기 전까지는 그 밑의 작업을 실행할 수 없다.
하지만 코드 전체를 보면 비동기적으로 작동하는 로직들이 많을 것이다.

이 코드는 동기다! 비동기에 논블로킹이다! 라고 하기가 힘들다.

∴블로킹/논블로킹, 동기/비동기는 일정한 영역에 한정적으로 봤을때는 추정할 수 있지만 코드 전체적으로 봤을때는 한가지로 단정지을수 없다.

Block/Non-block: 제어권. 제어할 수 없는 대상을 어떻게 처리하는가. 제어권을 누가 가지고 언제 반환하는가.
Synchronous/Asynchronous: 시간. 제어권을 반환하는 시간, 결과값을 전달하는 시간이 일치하는가
