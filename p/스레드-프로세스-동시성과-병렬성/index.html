CPU

CPU (Central Processing Unit) 는 기계의 일종의 두뇌
운영 체제와 다른 프로그램 또는 애플리케이션의 명령을 처리하는 역할
각 명령은 명령 주기(instruction cycle, fetch-execute 주기라고도 함)에 따라 실행

instruction cycle

  1. Fetch
  2. Decode
  3. Execute
  4. Memory Access
  5. Registry Write-Back

CPU는 사용 가능한 코어들 사이에서 처리 명령을 나누고 조정
CPU 코어: 개별 처리 장치. 프로그램과 다른 작업을 실행하는 역할

Process와 Thread

Process

프로그램

  • 컴퓨터에게 주어지는 어떠한 문제 처리 방법을 기술한 일련의 명령문을 포함하는 실행 파일
  • 이는 애플리케이션 프로그램 또는 시스템 프로그램일 수 있음.

애플리케이션 프로그램: 워드 프로세서, 게임, 구글 크롬 등
시스템 프로그램: 컴파일러, 파일 관리 프로그램 등

이러한 코드는 디스크에 저장되고 컴파일되어 메모리(RAM)에서 로드되어 프로세서(CPU)에 의해 실행

프로세서는 실행 중인 프로그램이며, 실행 중인 컴퓨터 프로그램의 인스턴스. 최소 1개의 메인 스레드를 보유

Thread

  • 쓰레드는 프로세스 내의 기본 실행 단위
  • 동일한 프로세스 내의 다른 독립적인 실행 흐름과 동일한 주소 공간을 공유하는 독립적인 실행 흐름
  • 프로세스는 하나 이상의 스레드를 가질 수 있음. 예시: Python 프로세스의 기본 스레드인 메인 스레드

Process vs Thread

구분 프로세스 (Process) 스레드 (Thread)
정의 운영체제에서 할당받는 자원의 단위 (실행 중인 프로그램) 프로세스 내에서 실행되는 작업의 단위
메모리 공간 서로 다른 프로세스는 독립적인 메모리 공간을 가짐 프로세스 내에서 메모리를 공유 (Code, Data, Heap 공유)
독립성 Code, Data, Stack, Heap이 독립적 Stack만 독립적으로 할당, 나머지는 공유
자원 공유 다른 프로세스와 자원 공유 불가 (IPC를 통해 제한적으로 가능) 같은 프로세스 내의 스레드끼리는 자원을 쉽게 공유 가능
상호작용 한 프로세스는 다른 프로세스의 메모리에 직접 접근할 수 없음 같은 프로세스의 스레드끼리는 서로 영향을 끼칠 수 있음
오버헤드 프로세스 생성/종료 시 오버헤드가 큼 스레드 생성/종료 시 오버헤드가 상대적으로 적음
예외 처리 한 프로세스의 오류는 다른 프로세스에 영향을 미치지 않음 한 스레드의 오류가 프로세스 전체에 영향을 줄 수 있음
속도 문맥 전환(Context Switching)이 느림 문맥 전환이 빠름
예시 웹 브라우저, 운영체제의 각 서비스 웹 브라우저의 탭, 파일 읽기 쓰기 스레드

IPC(inter process communication)의 종류로는 공유메모리, 파일, 소켓, 파이프, 메세지 큐가 있음. Thread Context Switching보다 Cost 높음

예를 들어 브라우저를 띄워서 네이버 서버와 HTTP 통신해서 html 등의 파일을 가져오는 것도 IPC라고 볼 수 있음

  1. 브라우저라는 프로그램을 실행. 메모리에 올라가면 프로세스가 됨.
  2. 주소창에 네이버 입력하게 되면 네이버라는 서버에다가 요청하는 것. -> 네이버 서버에서 어떤 프로세스를 띄워서 구동되는 것
  3. 즉 IPC다 라고 볼 수 있음. 프로세스와 프로세스가 정보를 요청하고 응답 받는 것이기 때문.

예시

브라우저는 멀티프로세스/멀티스레드를 기반으로 멀티프로세싱, 멀티스레딩을 함.

Browser Process: 주소창 등을 관리하는 프로세스
GPU Process: GPU 관련된 것들을 관리하는 프로세스
Plugin Process: 확장 프로그램 등 플러그인을 관리하는 프로세스
Renderer Process: 보이는 화면을 관리하는 프로세스

Renderer Process

  • Main thread
  • Worker threads
  • Compositor thread
  • Raster thread

여러개의 스레드 또는 프로세스를 만든 상태를 멀티스레드, 멀티프로세스. 이를 기반으로 작업을 하는 것을 멀티스레딩, 멀티프로세싱이라고 함.

Multiprocessing과 Multithreading

Multiprocessing

  • 여러 개의 프로세스, 즉 멀티프로세스를 통해 동시에 두 가지 이상의 일을 수행할 수 있는 것
  • 특정 프로세스 중 일부에 문제가 발생하더라도 다른 프로세스에 영향을 미치지 않음
    예시: kill -9 [PID] 명령을 한다고 종료한 프로세스와 관련 없는 다른 프로세스에 문제가 발생하지는 않음
  • 멀티프로세싱을 사용하여 여러 작업을 병렬로 실행하려면 컴퓨터에 최소 두 개의 CPU 코어가 있어야 함
    CPU 코어: 명령을 실행할 수 있는 CPU 내의 단일 처리 장치. 즉, CPU에 코어가 많을수록 병렬로 처리할 수 있는 작업이 많아짐
  • 그러나 동시 멀티스레딩(Simultaneous Multithreading, SMT) 또는 하이퍼스레딩(Hyper-Threading) 기술은 하나의 물리적 CPU 코어에 두 개 이상의 논리적 코어를 가질 수 있게 해서 하나의 코어로 여러 작업을 병렬로 실행할 수 있음

Use case

  • 멀티프로세싱이 가장 적합한 작업 유형은 대표적으로 CPU-bound 작업

CPU burst: 프로세스가 CPU에서 한 번에 연속적으로 실행되는 시간
CPU-bound 프로세스: CPU burst 작업이 많은 프로세스

수학적 계산, 데이터 압축, 코드 컴파일, 머신 러닝 등과 같이 완료 시간이 주로 프로세서(CPU) 속도에 의해 결정되는 작업

긴 타원은 완료하는 데 더 많은 시간이 걸리는 CPU-bound 작업

CPU bound 작업은 완료하는데 더 많은 시간이 걸리기 때문에 병렬로 실행하면 시간을 절약할 수 있음

두 작업을 동기적으로 실행하면 모두 완료하기까지 필요한 시간이 더 길어짐

완벽한 병렬성 없이 동시에 실행하더라도 이점이 없음

Multithreading

  • 하나의 CPU 코어에서는 여러 프로그램, 스레드가 동시에 실행될 수 있음

  • CPU 코어가 2개 이상이라면 동시에, 그리고 병렬로 실행될 수 있음.

  • 멀티 스레딩은 프로세스 내 작업을 멀티스레드로 처리하는 기법

  • 스레드끼리 서로 자원을 공유

  • 프로세스보다 가볍기 때문에 효율성이 높은 장점

  • 한 스레드에 문제가 생기면 다른 스레드에도 영향을 끼쳐 스레드로 이루어져 있는 프로세스에 영향을 줄 수 있음

아키텍처 예시: 브라우저. 멀티프로세스이자 멀티스레드 아키텍처를 가진 소프트웨어

Python GIL(Global Interpreter Lock)

여러 코어를 사용할 수 있더라도, Python 프로세스 내의 스레드는 Java, C/C++, Go와 같은 다른 프로그래밍 언어의 스레드와 달리 병렬로 실행할 수 없음

하지만 GIL이 해결할 수 없는 제약이 된다고 할 수는 없음

  • 병렬 처리는 multiprocessing 모듈, ProcessPollExecutor 클래스, asyncio등의 선택지 다양하게 있음
  • thread 병렬성 처리를 위해 Jython, IronPython, Stackless Python 등이 있음

Use case

  • 멀티스레딩이 가장 적합한 작업 유형은 대표적으로 I/O-bound 작업

I/O(Input/Output): 파일을 읽고 쓰거나, 네트워크상에서 데이터를 주고받거나, 모니터/ 마우스 같은 입출력 장치와 데이터를 주고 받는 것
I/O burst: 프로세스가 IO 작업을 요청하고, 그 결과를 기다리는 시간
I/O-bound 프로세스: IO burst 작업이 많은 프로세스

스레드가 데이터베이스에 데이터 요청 명령을 실행하는 경우
스레드가 응답을 기다리는 동안 CPU 코어를 차단하는 것은 의미가 없음
-> 첫 번째 스레드가 기다리는 동안 다른 스레드가 코어를 사용할 수 있도록 하는 것이 리소스를 더 효율적으로 사용하는 것

빈 원은 스레드가 무언가가 발생하기를 기다리는 I/O 작업 첫 번째 I/O 작업이 시작되면(빈 녹색 원) 운영 체제는 계산 리소스를 더 잘 할당하기 위해 대기 스레드를 빨간색 스레드로 빠르게 전환 이는 OS 가 내리는 결정이며 개발자는 스레드 간에 언제 전환할지 결정할 수 없음

두 작업을 동기적으로 실행하면 모두 완료하기까지 필요한 시간이 더 길어짐 따라서 I/O 작업을 처리할 때 멀티스레딩을 사용하면 리소스를 보다 효율적으로 할당할 수 있음

코루틴(Coroutine)

루틴

  • 일련의 명령(코드의 흐름)

메인 루틴

  • 프로그램의 메인 코드의 흐름

서브 루틴

  • 우리가 알고 있는 보통의 함수나 메소드 (메인 루틴을 보조하는 역할)
  • 하나의 진입점과 하나의 탈출점이 있는 루틴

코루틴

  • 서브 루틴의 일반화된 형태
  • 다양한 진입점과 다양한 탈출점이 있는 루틴
  • 코루틴은 서브루틴과는 달리 해당 로직들이 진행되는 중간에 멈추어서 특정 위치로 돌아 갔다가 다시 코루틴에서 진행되었던 위치로 돌아와 나머지 로직을 수행할 수 있음

import time

def delivery(name, mealtime):
    print(f"{name}에게 배달 완료!")
    time.sleep(mealtime)
    print(f"{name} 식사 완료, {mealtime}시간 소요...")
    print(f"{name} 그릇 수거 완료")

def main():
    delivery("A", 5)
    delivery("B", 3)
    delivery("C", 4)
    # return None <- 생략 되어 있음

if __name__ == "__main__":
    start = time.time()
    main()
    end = time.time()
    print(end - start)
  • 예시 스크립트에선 서브 루틴은 두 가지가 있음. 메인 루틴 안에 main()함수가 있고, main() 서브루틴이 실행 되면서 그 안에 또다른 서브 루틴 delivery()가 실행 됨.
  • 서브 루틴은 함수이고 함수는 input 값이 있으면 return 값이 있는 구조. 즉, 하나의 진입점과 하나의 탈출점이 있는 루틴.
  • 코루틴은 다양한 진입점과 다양한 탈출점이 있기 때문에 서브 루틴의 일반화된 형태라고 함

import time
import asyncio


async def delivery(name, mealtime):
    print(f"{name}에게 배달 완료!")
    await asyncio.sleep(mealtime)
    time.sleep(mealtime)
    print(f"{name} 식사 완료, {mealtime}시간 소요...")
    print(f"{name} 그릇 수거 완료")
    return

async def main():
    await asyncio.gather(
        delivery("A", 1),
        delivery("B", 1),
        delivery("C", 1),
    )
    # return None <- 생략 되어 있음

if __name__ == "__main__":
    start = time.time()
    asyncio.run(main())
    end = time.time()
    print(end - start)
"""
A에게 배달 완료!
B에게 배달 완료!
C에게 배달 완료!
A 식사 완료, 1시간 소요...
A 그릇 수거 완료
B 식사 완료, 1시간 소요...
B 그릇 수거 완료
C 식사 완료, 1시간 소요...
C 그릇 수거 완료

-> 
await asyncio.sleep(mealtime)에서 탈출을 하고
다시 await asyncio.sleep(mealtime)로 진입을 하게 됨
원래는 async def delivery(name, mealtime):로 진입했었음
즉, 진입점 2개, 탈출점이 2개가 있음
"""
  • 코루틴은 파이썬만 있는게 아니라 javascript, golang등 다양한 언어에서 지원
  • 예시의 delivery()와 같은 함수를 코루틴 함수라고 함. 코루틴 함수로 비동기 코드를 작성할 수 있음
  • 따라서, 파이썬 비동기 함수는 코루틴 함수로 작성할 수 있다고 볼 수 있음

간단하게 정리하자면

  • 코루틴은 다양한 진입점과 다양한 탈출점이 있는 함수
  • 서브루틴은 하나의 진입점과 하나의 탈출점이 있는 일반적인 함수

라고 생각할 수 있다.

코루틴의 장점

  • 쓰레드에 비해 오버헤드 감소. 에시: 쓰레드는 컨텍스트 스위칭 비용 발생이 큼

코루틴은 단일(싱글) 스레드에서 스택을 기반으로 동작하는 비동기 작업. 단일 스레드내에서도 동시성 프로그래밍 할 수 있도록 발전

Concurrency과 Parallelism

빨간색 작업이 실행을 시작하려면 녹색 작업이 먼저 완료되어야 함. 채워진 각 원은 수행해야 할 명령

Concurrency

동시성은 여러 작업 또는 프로세스의 실행이 시간적으로 겹치는 것

시간적으로 겹치지만 둘 다 같은 순간에 실행되지 않을 수도 있음
-> 반드시 물리적으로 동시에 즉, 병렬로 실행되지 않을 수 있음(작업 스위칭)

Parallelism

병렬성은 여러 작업 또는 프로세스가 물리적으로 동시에 실행되는 것

∴ 동시성은 시간적으로 겹치는 작업을 포함하는 더 광범위한 개념

  • 두 작업을 병렬로 실행하면 많은 시간을 절약
  • 두 개의 프로세스, 스레드 또는 작업이 병렬로 실행되면 동시에 실행됨

동시성에서 말하는 동시(Concurrent)
병렬에서 말하는 동시(Simultaneous)

Concurrency and Parallelism Scenarios

기본적으로 여러 작업을 병렬로 실행하려면 최소 두 개의 CPU 코어가 필요
(동시 멀티스레딩(Simultaneous Multithreading, SMT) 또는 하이퍼스레딩(Hyper-Threading) 기술로 하나의 코어만으로 여러 작업을 병렬로 실행할 수 있지만 지금은 기본적인 내용으로)

1 process, 1 thread, 1 core

✅ 동시성

  • ❌ 멀티스레딩을 통한 동시성은 없음
  • ✅ 코루틴을 사용한 동시성

1 process, n threads, 1 core
✅ 동시성
❌ 병렬 처리 없음(예외: 하이퍼 스레딩)

1 process, n threads, 2 cores
✅ 동시성
✅❌ 병렬 처리 여부는 프로그래밍 언어에 따라 달라짐
(Python의 각 프로세스 내의 스레드는 Python의 GIL(Global Interpreter Lock)로 인해 실제로 병렬로 실행될 수 없음. Java, C/C++, Go 등 다른 프로그래밍 언어의 스레드와는 다름)

2 processes, n threads, 1 core
✅ 동시성
❌ 병렬 처리 없음(예외: 하이퍼 스레딩)

2 processes, n threads, 2 cores
✅ 동시성
✅ 병렬성, 두 프로세스는 병렬로 실행될 수 있음

Advantages and Disadvantages

Advantages

리소스의 보다 효율적인 할당과 그에 따른 시간 절약 cost-effective(비용 효율)

  • 스레드 컨텍스트 스위칭은 프로세스 컨텍스트 스위칭보다 비용 효율적
  • 파이버(fibers)와 코루인(Coroutine)과 같이 컨텍스트 전환 비용을 최소화하는 메커니즘도 있음
  • 코루틴은 스레드 컨텍스트 스위칭보다 비용 효율적
  • 프로세스 컨텍스트 스위칭 cost > 스레드 컨텍스트 스위칭 cost > 코루틴 cost

Disadvantages

복잡성 증가

  • 동시성과 병렬성을 다룰 때 새로운 문제가 발생(예시: race conditions)
  • 충돌을 피하기 위해 locking(잠금), semaphores(세마포어), optimistic concurrency control(낙관적 동시성 제어), transaction management(트랜잭션 관리)등 여러 기법을 사용해 공유 리소스를 신중히 관리

Conclusion

동시 프로그래밍은 고성능 시스템을 개발하는 데 도움이 되는 매우 강력한 도구이지만, 복잡성을 수반하기 때문에 심도 있게 연구해야 하는 주제
